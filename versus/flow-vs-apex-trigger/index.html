Flow vs Apex trigger vs scheduled & batch

A record changes and something else needs to happen. Where does the automation live?

Before-save flowAfter-save flowApex triggerScheduled flowBatch Apex

The matrix

Find your situation in the left column. Green means a committed answer; amber means the honest answer is a trade-off — the note says on what.

Your situationPickWhy
Update fields on the record being savedBefore-save flowRuns before the write, no extra DML, roughly 10x faster than after-save. This one is not a judgment call.
Create or update other records when something changesAfter-save flowApex triggerAfter-save flow if the logic is simple and admins will own it. Trigger once you need collections, complex branching, or real unit tests.
Logic needs unit tests, code review, or version control rigorApex triggerFlows have no assertable unit tests worth the name. If a bug here costs real money, you want Apex and a test class.
Guaranteed execution order across many automations on one objectApex triggerOne trigger per object delegating to a handler class is the only place order is fully explicit. Flow trigger ordering exists but is easier to get wrong silently.
Call an external system when a record changesIt dependsNeither, directly — callouts cannot run inside the save transaction. Use an after-save flow's asynchronous path, or a trigger that enqueues a Queueable. For fan-out to multiple systems, consider a platform event instead.
Run nightly against records matching criteriaScheduled flowFine up to modest volumes. Watch the per-run element limits; a scheduled flow iterating 200k records is a governor-limit incident on a timer.
Process hundreds of thousands to millions of rowsBatch ApexChunked transactions with restart logic exist precisely for this. Nothing declarative survives at this scale.
No Apex capacity on the teamBefore-save flowAfter-save flowScheduled flowLegitimate constraint — but budget for the day the org outgrows it, and keep the flow inventory documented so that migration is possible.

Rule of thumb

  • Same-record field updates: before-save flow, always. This is the one answer with no caveats.
  • Cross-object and simple: after-save flow. Cross-object and complex, ordered, or money-critical: one trigger per object with a handler class.
  • Callouts never run in the save. Async path, Queueable, or a platform event — pick one and be consistent.
  • Above ~100k rows per run, it is Batch Apex. Scheduled flows at that volume fail on a timer.
  • The real killer is mixing: five flows and two triggers on one object with no documented order. Keep an automation inventory per object.
